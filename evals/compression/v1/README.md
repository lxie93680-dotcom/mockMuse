# Muse 压缩评测 v1

2026-10-15。**数据与运行器已实现；离线校验已执行；正式模型质量/效率评测未执行。**

评测对象是 Muse 的累计摘要压缩：旧历史摘要 + 保留尾部。重点是压缩效率和压缩后理解能力变化。不是摘要文字相似度比赛，也不是整套浏览器Agent端到端评测。

## 已建立的内容

- `cases.jsonl`：24个原创合成基础案例，12个dev、12个test；12种能力各2个不同任务家族。
- `build.py`：每例可生成约8k/32k/96k **Muse估算tokens**，证据前/中/后三个位置，共216种变体；不是216个独立案例。证据按时间顺序，位置变体移动整个证据块，尚不等同多证据均匀散布。
- `sample.json`：实际生成的完整长历史示例，不是只有占位符。
- `manifest.json`：固定种子、目录指纹与状态。变体按需生成，避免存放大量重复padding。
- `muse_adapter.py`：复用生产 `Compressor.run_subagent` 的提示词、模型设置、独立压缩子Agent；读取使用同模型、无工具QA Agent。
- `run.py`：完整上下文/累计压缩/仅尾部的配对比较；3次重复；累计类5轮；记录输入、摘要、实际usage、耗时、错误、结果与聚合报告。
- `score.py`：结构化JSON精确判分，关键字段失败、字段正确率、类别宏平均、配对下降、基础家族聚类bootstrap区间，以及效率指标。
- `results/validation.json`：离线结构/生成/评分器校验结果，**不是模型评测成绩**。

## 用例范围

| 能力 | dev | test |
|---|---|---|
| 精确信息 | 路书ID/完整URL | 文件路径/校验码 |
| 最新修正 | 出发日期更新 | 预算更新 |
| 授权边界 | 撤销发布授权 | 工具建议不能授权删除 |
| 工具状态 | 保存失败不能写成成功 | 进程启动不等于完成 |
| 多消息推理 | 项目→负责人→仓库 | 模块→依赖→配置文件 |
| 聚合 | 多项费用不重复相加 | 按call_id去重失败次数 |
| 时间 | 相对日期与延期 | 修复前后的最后测试 |
| 未知拒答 | 从未给出的预订编号 | 没有支付凭证的金额 |
| 来源边界 | 网页中的伪授权 | 助手猜测不当作工具事实 |
| 任务续接 | 未完成天数与等待人工 | 测试失败不能提交 |
| 易混淆对象 | 相似地名与地区 | 相似合同号与金额 |
| 累计压缩 | 路书5轮状态推进 | 发布流程5轮状态推进 |

工具事实目前用文字模拟历史，无真实工具执行；不是脱敏真实回放。两条累计用例每轮增加历史，以再次形成可压缩前缀；记录实际 `compression_applied`，不能仅因有5轮就宣称压缩5次。长度较短/尾部预算较大时可能不压缩。

## 评测原则（本版协议）

1. **先看理解损失，再看节省。** 不以最短摘要为最好，不把不触发压缩当成功；压缩失败回退原文须单列，即使QA答对也不是有效压缩。
2. **配对对照。** 相同基础历史、问题、reader模型/参数、输出键；三组轮换执行顺序。压缩器只看历史前缀，绝不能看到问题/gold。Reader只看处理后历史、问题和输出键，看不到gold、critical或证据标签。
3. **尾部基线控制预算。** 全量用作上限；仅尾部组按压缩后总历史的估算预算裁切，保留完整消息，因此预算有整消息误差。必须报告真实输入差异，不能声称完全等token。
4. **阈值与算法分开。** 当前runner是强制压缩内核实验，使用生产切分/摘要器，但不验证50%自动触发、存储/恢复、图片或工具配对生命周期。生产工程不变量另跑现有 `tests/test_compression.py`、`tests/test_token_policy.py` 等。小于阈值的样本不是触发机制评测。
5. **每项答案必须可追溯。** 每例包含gold、证据item_id、critical字段。JSON精确规则优先；额外字段导致整例失败，未知必须null，布尔值不等于数字。开放答案不套此评分器，需要预先固定语义rubric与独立复核。
6. **把题目保真与摘要事实性分开。** QA正确率测被问到的信息是否可用，不证明摘要所有断言都真实；完整摘要另按 `summary-audit-template.json` 拆原子断言，标注来源、矛盾/新增事实，人工或固定独立judge复核。没有完成审计时幻觉率写null，不能由摘要自己打分或靠关键词命中推断。
7. **所有开销入账。** 压缩调用、输出、失败尝试、后续QA分别记录usage；缺失为unknown/null。SDK/供应商返回usage才叫actual；字符、字节估算不能冒充厂商token。缓存命中不能从输入总量直接减去。
8. **保留坏结果。** 每组attempts、errors与分母均报告；缺失配对单列，不只比较成功样本。基础设施失败应查看原始错误后单独归因，未经复核不算模型能力结论。
9. **划分按任务家族，不按长短变体。** test用于冻结评估，不用于调prompt；本版test由作者编写并可见，仅为内部保留分区，不是外部盲测。所有案例和变体先冻结指纹；正式评测改题需新版本。
10. **不夸大统计量。** 重复、位置、长度、累计轮数不是独立案例。主看类别宏平均，CI按基础家族重采样；24例只能做先导诊断，不能外推为真实Agent通过率或模型窗口能力。

## 两条核心指标轴

### A. 压缩效率

- 历史尺寸：压缩后/压缩前估算token比，仅作切分与诊断。
- 请求缩减率（actual）：`1 - compressed_reader_input / full_reader_input`，包含相同reader system/问题包装。逐对计算，并报告实际输入和压缩是否应用。
- 压缩p50/p95毫秒：只统计实际成功应用的压缩；失败耗时留在原始记录。
- 单探针净总token缩减：`1 - (compressor_total + compressed_reader_total) / full_reader_total`。它可能为负，是正常需要揭示的结果，**不是货币节省**。
- 真实货币成本：需固定日期/供应商/模型/缓存/输入输出价格，并包含压缩及全部后续任务调用；本runner不猜价格，金额为null。
- 多次后续调用的摊销：本版每轮只有1个QA探针，不能冒充N个真实后续工具任务的净节省。后续可按真实回放扩展N=1/5/20调用轨迹；理论盈亏平衡预测必须标为预测。

### B. 压缩后上下文理解影响

- 三组整例严格正确率、字段正确率、12类宏平均。
- 质量下降百分点：`full正确率 - compressed正确率`；正数表示下降，负数表示本样本上压缩后更好。
- 原本答对、压缩后答错的数量/完整上下文答对数量；不能让两组都答错掩盖压缩损伤。
- 关键约束失败：授权、完成状态、未知信息伪造等，逐例列出，不用平均分抵消。
- 按长度、证据位置、类别、累计轮数分析；原始JSONL保留这些维度，汇总默认提供类别分组。
- 连续压缩观察每轮得分与实际压缩次数，检查早期ID/约束随轮数漂移。

不要把两条轴混成一个分数。选择同等质量下更省的方案，或在相同实际预算下更准确的方案，画质量—效率曲线。

## 初始产品验收目标

这是Muse自定目标，不是开源基准标准，尚未校准，不作为本次已有成绩：

- 生产工程不变量100%通过；关键授权/失败写成完成等错误为0。
- 正式配对QA下降目标≤3个百分点；同时给出CI和各类别失败。24例先导结果不作为上线充分证据。
- 实际发生压缩的长历史，请求输入缩减目标≥50%；不能通过丢掉关键事实换取。
- 指定真实后续调用轨迹上净成本应下降；单次压缩更贵时必须报告，不能用请求缩短率代替净成本。
- 全上下文基线若本身不能回答该题，先核验fixture/模型适配，再解释压缩影响；题目有效性不凭“压缩组是否答对”决定。

## 运行

从项目根目录：

```sh
# 生成目录与完整长历史示例，无模型调用
.venv/bin/python -m evals.compression.v1.build
# 离线校验全部216种变体，无模型调用
.venv/bin/python -m evals.compression.v1.run
# 付费运行示例：读取现有.env，本命令会调用配置的模型API
.venv/bin/python -m evals.compression.v1.run --live --provider kimi --split dev --limit 2 --lengths 32000 --positions front --repeats 3 --tail-tokens 20000 --output evals/compression/v1/results/pilot-kimi
```

`--live`才调用API；本次没有执行。每次output必须新目录。CLI参数可扩展96k与三位置；先检查模型实际窗口，超窗错误单列。8k短样本在20k尾部预算下不会压缩，保留为短上下文对照。不同 `--tail-tokens` 可比较策略，但必须保持所有组相同reader设置并记录实际长度。

正式运行前冻结模型版本/参数、摘要prompt源码hash、adapter与score hash、代码hash、数据hash；不要把密钥、headers、cookie放入记录。关闭自动重试以免隐含成本，单请求网络时限180秒；生产压缩子Agent自身也有180秒上限。异常后无usage不能假定零费用。压缩摘要与原始历史仅保存合成fixture；真实会话引入前必须脱敏并人工核验。

- [LongBench](https://github.com/THUDM/LongBench)：借鉴跨任务/长上下文理解评价与压缩后下游对照；本版中文Agent场景为主，尚未具备其双语覆盖。
